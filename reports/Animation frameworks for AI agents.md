# Build the skill around timing, not frameworks

No single open-source framework beats the stack you already proved on "Initial Condition". The best build is a hybrid. Keep the voice-driven timeline, the audio mixer and the segment and stills renderer from the pycairo + numpy + OpenCV + ffmpeg pipeline as the backbone, and let it call more than one picture backend. **The extracted pycairo engine stays the default** for stylized vector-plus-plate films. **HyperFrames (Apache-2.0, HTML/CSS/GSAP rendered headless in Chrome)** comes second, for typography, kinetic text, diagrams and data shots. Add **Blender 5.2 LTS** later for shots that need real depth, occlusion or 3D characters. A new **local-video skill (Wan 2.2 or LTX-2.x through ComfyUI)** animates Qwen-Image plates and makes transitions. It never carries the story. Published evidence says the harness matters more than the framework or the model. An agent harness with a planner, a layout system, a render-and-fix loop and a frame critic lifted every model by about 40-50 points over writing the code directly ([Code2Video](https://arxiv.org/html/2510.01174)). The remaining failures are visual, not syntactic: timing between beats, text that collides mid-motion, and flat "safe" layouts ([HeyGen Research](https://www.heygen.com/research/introducing-code2video-benchmark)). Your word-timestamp cue system already handles timing better than most published systems. For licences, an individual in the EU can use everything recommended here. You must avoid HunyuanVideo 1.5, whose licence explicitly excludes the EU, and probably FramePack, which is built on it. Remotion is free for you today, but it is source-available, not open source. The 20-second benchmark should run in two tracks: one with frozen assets that isolates code-writing, and one that goes from idea to film. Each agent arm gets three runs under identical budgets, and blind human pairwise judging decides, because automated judges agree poorly with people.

## Five tools pass the headless, deterministic, Windows filter

The question decides itself on a few hard requirements. The agent must render from a command line without a window. It must render the same frame identically every time. It must be able to render single frames for review, because the agent cannot watch video. It must run offline on Windows 11. Five candidates clear all of these: your pycairo stack, Manim Community Edition, Remotion, HyperFrames and Blender. A second tier works with caveats. Motion Canvas, Theatre.js, OpenToonz and Spine fail for structural reasons.

The failures are instructive. **Motion Canvas renders only from its browser editor's RENDER button** ([Motion Canvas docs](https://motion-canvas.io/docs/rendering)), and it has shipped nothing since February 2025. **Theatre.js moved development to a private repo in April 2024** and has had no public commits since ([Theatre.js README](https://github.com/theatre-js/theatre)). Spine's CLI still needs "an OS windowing system and OpenGL" to export video ([Spine CLI docs](https://esotericsoftware.com/spine-command-line-interface)), and Spine requires a paid editor licence. OpenToonz 1.8.0 (June 2026) revived the traditional cel pipeline after three quiet years ([Impress Watch](https://forest.watch.impress.co.jp/docs/news/2118799.html)), but it is built for drawing by hand, not scripting. Synfig renders headless, including single frames with `--time` ([synfig manpage](https://manpages.ubuntu.com/manpages/lunar/man1/synfig.1.html)). Its last stable release, though, is 1.4.5 from May 2024 ([Synfig releases](https://www.synfig.org/category/releases/stable-releases/)), and its `.sif` XML is rare in training data. Godot 4's `--write-movie` with `--fixed-fps` gives deterministic offline capture ([Godot docs](https://docs.godotengine.org/de/4.4/_sources/tutorials/animation/creating_movies.rst.txt)). It is a capable real-time option, but the template would have to add its own seek-to-time hook for stills.

The GPU matters less than you would expect. Manim CE's default Cairo renderer runs on the CPU, though v0.21 made it 2.2x faster on animation-heavy scenes. Your own stack is also CPU-bound and scales with worker processes. Browser engines use the RTX 5080 only when told to. Remotion warns that "by default in many cases, the GPU is disabled in headless mode", and that the `angle` backend has known memory leaks on long renders ([Remotion GPU](https://www.remotion.dev/docs/gpu), [gl-options](https://www.remotion.dev/docs/gl-options)). HyperFrames uses **screenshot-based multi-worker capture on Windows**, while Linux gets the faster BeginFrame path ([HyperFrames docs](https://github.com/heygen-com/hyperframes/tree/main/docs)), so expect slower renders on Windows than the project advertises. Blender is the one tool here that turns the 5080 into real speed. Its Blender benchmark score of about 9,130 sits roughly 4.5% above an RTX 4080 ([Renderjuice](https://www.renderjuice.com/gpus/compare/rtx-4080-vs-rtx-5080)). But the 5.2 release page lists open "bright red artifacts" on 50-series GPUs ([Blender 5.2](https://www.blender.org/releases/5-2/)), so render a test still after every driver or Blender update. Nobody has published comparable seconds-per-frame benchmarks across these frameworks, so the demo should measure them.

Licensing splits cleanly. Manim, Motion Canvas, Revideo, HyperFrames, MoviePy and Godot use permissive licences, and Blender is GPL. None of these restricts what you render. Remotion is the exception. It is **free for individuals, for-profit organisations of up to three employees and non-profits**. Larger companies pay **$25 per month for each person who writes Remotion code, including through agentic coding tools**, or **$0.01 per render with a $100 monthly minimum** ([Remotion License FAQ](https://www.remotion.dev/docs/license/faq)). The open Remotion 5.0 PR adds that "contractors also count towards team size" ([PR #3750](https://github.com/remotion-dev/remotion/pull/3750)). As a solo creator you qualify today. The risk appears only if this tooling moves into a company or ships inside a product: the licence forbids selling "your own derivate of Remotion". python-lottie's AGPLv3 matters only if you ship it in a networked service. Every candidate runs offline once installed. Revideo counts renders through PostHog unless you set `DISABLE_TELEMETRY=true` ([Revideo README](https://github.com/midrender/revideo)).

## The harness matters more than training exposure

The intuitive rule says to pick the framework models know best. The evidence says that matters less than how the agent is harnessed. Manim has the most training exposure and the most published research, and it shows how exposure backfires. In Code2Video's tests, Claude Opus 4.1 writing Manim directly scored **37.8 on aesthetics. Inside a Planner → Coder → Critic agent the same model scored 87.9**, the best of all backbones. Removing the planner alone dropped GPT-4.1 from 79.0 to 38.1 ([Code2Video](https://arxiv.org/html/2510.01174)). TheoremExplainAgent found Manim API hallucination to be the top failure, ahead of LaTeX errors. With five retries, o3-mini reached 93.8% render success ([TheoremExplainAgent](https://arxiv.org/html/2502.19400)). ManiBench documents **145 ManimGL→CE incompatibilities** that models mix up. In its pilot, which had only 12 problems, zero-shot executability was 0.667 for Claude Sonnet 4 and **0.000 for both Gemma-3-27B and Qwen-2.5-Coder** ([ManiBench](https://arxiv.org/html/2603.13251v1)).

The same studies show how to close the gap. Two cheap fixes worked for a 27B model in ManiBench. Listing the forbidden constructs explicitly ("version-aware prompting") cut Gemma-3-27B's version conflicts to zero. Few-shot examples were the only strategy that raised executability, by 11.1 points. Chain-of-thought made conflicts worse ([ManiBench](https://arxiv.org/html/2603.13251v1)). Retrieval over the docs is not a free win. In TheoremExplainAgent it helped the weakest model, Claude 3.5 Sonnet (2.1% → 14.6%), and hurt the strongest, o3-mini (93.8% → 82.1%) ([TheoremExplainAgent](https://arxiv.org/html/2502.19400)). The most encouraging local result: **Qwen 3 Coder 30B, tuned with GRPO and run with the renderer in the loop plus API docs, reached 94% render success and 85.7% visual similarity**, about three points above a GPT-4.1 baseline ([ManimTrainer abstract](https://deeplearn.org/arxiv/815516/training-and-agentic-inference-strategies-for-llm-based-manim-animation-generation)). That model was fine-tuned, while yours is a general model, so the result shows what a tight renderer loop can do. It does not predict your local model's score.

Blender has the same problem, because its API keeps moving. Grease Pencil v3 replaced v2 in 4.3, `Sequence` became `Strip` in 4.4, and 5.0 removed the legacy Action API and `scene.node_tree` and renamed the Eevee engine identifier ([4.3 GP migration](https://developer.blender.org/docs/release_notes/4.3/grease_pencil_migration/), [4.4 notes](https://developer.blender.org/docs/release_notes/4.4/python_api/), [5.0 notes](https://developer.blender.org/docs/release_notes/5.0/python_api/)). Retrieving expert examples raised Blender code compilation success **from 40.8% to 70.0%** across four LLMs ([BlenderRAG summary](https://chatpaper.com/chatpaper/paper/274387)). Even so, Blender is the right 3D pin. 5.2 LTS freezes the API until July 2028, and `--python-exit-code` gives the agent a clean failure signal. Pair it with a cheatsheet of 5.x idioms.

The browser-based tools win on what the code is written in. HyperFrames code is mostly plain HTML, CSS and GSAP, which every model, a 27B local one included, has seen far more often than any animation DSL. Only its timing contract (`data-*` attributes, paused timelines, no wall-clock reads, no unseeded randomness) is new. That contract "fails quietly" when broken ([HyperFrames guide](https://hyperframes.heygen.com/guides/hyperframes-vs-remotion)), so you need its linter and its skills. Remotion and HyperFrames are the only frameworks with **first-party agent skills**. Remotion deprecated its MCP server because "agents do not invoke them reliably" and moved to skills plus Markdown docs: append `.md` to any docs URL ([Remotion MCP](https://www.remotion.dev/docs/ai/mcp), [Remotion AI docs](https://www.remotion.dev/docs/ai/)). That is a useful design signal for your own tool. A skill with a curated reference beats an MCP wrapper, and Claude Code's Bash tool already covers "write a file, run the renderer, look at stills".

Your pycairo engine is the outlier. No model has seen its API, but every library under it (pycairo, numpy, OpenCV, ffmpeg) is stable and well represented in training data. The skill's own reference and examples therefore act as retrieval by construction. That is the setup that worked best for weak models in the studies above, and the API cannot drift. The hardest open fact is that **nobody has published Haiku, current Sonnet or a dense Qwen 27B on animation code in a shared harness**. HeyGen's September 2026 benchmark, run on HyperFrames, puts claude-opus-5 third. The top four models are within 12 Elo of each other, and the best open-weight models are within 50 Elo. Sonnet and Haiku were not tested ([HeyGen Research](https://www.heygen.com/research/introducing-code2video-benchmark)). Your benchmark would fill a real gap.

## Word timestamps and stills decide the agent's loop

Two capabilities matter most to an agent that cannot watch its own film. The first is tying visual beats to spoken words. The second is producing cheap stills to look at. On narration sync, your system is ahead of the published ones. **manim-voiceover triggers animations at specific words via Whisper** ([manim-voiceover](https://github.com/ManimCommunity/manim-voiceover)). Its built-in TTS engines are mostly cloud services, though, so local TTS needs a custom service class. TheoremExplainAgent's local Kokoro service shows this can be done ([TheoremExplainAgent repo](https://github.com/TIGER-AI-Lab/TheoremExplainAgent)). Remotion installs whisper.cpp locally and produces token-level timestamps for captions ([Remotion whisper.cpp](https://www.remotion.dev/docs/install-whisper-cpp/)). HyperFrames bundles local Kokoro TTS, Whisper or Parakeet transcription, caption effects and a voiceover-ducking mixer ([HyperFrames README](https://github.com/heygen-com/hyperframes)). The Hermes `manim-video` skill hard-codes `run_time` and `wait()` values and adds audio afterwards ([Hermes docs](https://hermes-agent.nousresearch.com/docs/user-guide/skills/bundled/creative/creative-manim-video)). Most research systems likewise time by scene, not by word. Your setup goes further. Cue specs like `"L27:end+0.3"` resolve against Whisper word timings, pin slots hold later shots in place when a take shrinks, and the mix is built outside the renderer (LESSONS). HeyGen's top failure mode was that models "hit every beat" but "the timing between beats breaks" ([HeyGen Research](https://www.heygen.com/research/introducing-code2video-benchmark)). That is exactly what deriving timing from word timestamps, rather than letting the model choose durations, prevents. So the timeline must be a separate, renderer-independent `timeline.json` that any backend can read. Use frame offsets for HyperFrames `data-*` attributes, keyframes for bpy, and `s.c(...)` for pycairo.

On the review loop, all five leading tools can render stills. Remotion renders `--frames=0,30,60` lists ([CLI](https://www.remotion.dev/docs/cli/render)). HyperFrames has `snapshot --at 0,3,8` plus static `lint` and `check` passes ([HyperFrames docs](https://github.com/heygen-com/hyperframes/tree/main/docs)). Blender takes comma lists and steps, so `-j 48` gives a two-second contact sheet at 24 fps ([Blender manual](https://docs.blender.org/manual/en/latest/advanced/command_line/arguments.html)). Manim can render a last frame, and `--format none` runs the scene without writing media as a fast check ([v0.22.0](https://github.com/ManimCommunity/manim/releases/tag/v0.22.0)). Manim cannot jump to an arbitrary time inside a scene, though, because it must play through the earlier animations. The browser engines and your segment renderer can seek any frame directly. One finding should change how you review: **text collides along its motion path, not in the final frame**. HeyGen reports layouts designed "for the final frame, not for the path it travels" ([HeyGen Research](https://www.heygen.com/research/introducing-code2video-benchmark)). Code2Video's human raters also penalised brief occlusions that VLM judges missed ([Code2Video](https://arxiv.org/html/2510.01174)). The skill should sample several frames inside each animation, not one still per shot.

Code2Video also shows a structural fix worth copying. It maps the frame onto a **6×6 grid of anchor points** and keeps an occupancy table linking every element to its anchors, scale and source line. A critic can then trace an overlap back to code. The grid ablation lost 9.8 aesthetic points, and 6×6 beat both 4×4 and 8×8 ([Code2Video](https://arxiv.org/html/2510.01174)). Your engine can log bounding boxes per frame to the same kind of table. Overlap, safe-margin and "leftover guide shape" checks then become automatic gates, like your existing palette guards, instead of things the agent has to notice by eye.

## Local video models make plates, not stories

Video generation on 16 GB is now usable, but only for a narrow role. Three families fit with quantization or offloading, and they produce about 81-121 frames (3.4-5 s) at 480p-720p per generation. **Wan 2.2** (July 2025, Apache 2.0) has the deepest ecosystem. That includes a 5B model that fits in 8 GB, 14B MoE models that fit 16 GB with FP8 or GGUF quantization and block swap, a native first-last-frame mode, and lightning LoRAs ([ComfyUI Wan 2.2 docs](https://docs.comfy.org/tutorials/video/wan/wan2_2)). **LTX-2.5** (August 2026) is a 22B audio-video model with distilled int8 and **NVFP4 builds that target Blackwell cards such as the 5080**. It supports first/last-frame, union-control IC-LoRA (depth, canny, pose) and a built-in 2x upscaler ([Lightricks LTX-2.5](https://huggingface.co/Lightricks/LTX-2.5), [ComfyUI Wiki](https://comfyui-wiki.com/en/news/2026-08-11-ltx-2-5-open-weights-release)). Its fit on 16 GB is contested: one hands-on test measured 47 GB at 2 megapixels. **HunyuanVideo 1.5** needs 14 GB with offloading. Newer Wan versions (2.5, 2.6, 3.0) are API-only ([Atlas Cloud](https://www.atlascloud.ai/blog/tips/is-wan-3.0-open-source)).

The EU location matters in one place. Tencent's licence says it "DOES NOT APPLY IN THE EUROPEAN UNION, UNITED KINGDOM AND SOUTH KOREA" ([Hunyuan licence](https://huggingface.co/tencent/HunyuanVideo-1.5/blob/main/LICENSE)), so for you HunyuanVideo has no licence at all. FramePack's released model is, from prior knowledge, a HunyuanVideo fine-tune, so treat it the same way until you have checked. This research did not cover the licences of the models behind your existing local-image, local-voice and local-sounds tools. Check those model cards for the same territory clauses.

The strengths of these models are the opposite of your engine's. They are good at fog, water, embers, light and slow camera moves, and at animating a still image. They are poor at exactly what the "Initial Condition" notes kept flagging: proportion, held objects, physical causality, legibility and holding identity across shots ([AI Video Sensei](https://aivideosensei.com/guides/ltx-2-local-setup)). So the generated layer should always sit under authored layout. There are three safe patterns. Image-to-video turns a Qwen-Image plate into a drifting, living background. First-last-frame (FLF) generation between two plates makes a transition. And "procedural guide → generated look" uses LTX IC-LoRA or Wan control models to repaint a pycairo or Blender render. LTX's docs name "Blender synthetic depth renders" as a valid control input, and they warn that the depth range must stay consistent or the output flickers ([LTX IC-LoRA](https://docs.ltx.video/open-source-model/usage-guides/ic-lo-ra)). Two constraints shape scheduling. Every 16 GB recipe already fills the card, so video generation runs as a batch phase with the image, voice and SFX servers stopped. And no source documents bit-exact reproducibility, so store each take's workflow JSON, seed and output file as the source of truth. ComfyUI's `/prompt` API with seed injection is the same pattern your local-image skill already uses ([ComfyUI API guide](https://eastondev.com/blog/en/posts/ai/20260724-comfyui-api-batch-automation/)).

## Recommended build: one timeline, two picture backends, one plate generator

**Do the local-voice fixes first.** Aligned dry stems, word timestamps in the take JSON, and warnings for extra vocalizations and bass-heavy takes would remove about 200 lines of workaround code. They also turn timing into data that every backend reads in the same way. Then build the `narrated-animation` skill in this order.

**1. The core: the "Initial Condition" method plus a slim engine.** Extract the about 2,000 reusable lines as the LESSONS file proposes. That covers the voice-driven timeline and cue specs, the segment renderer with resume and stills, the mixer and mux, contact sheets and checks, plus a `WORKFLOW.md` that encodes the outline → script → storyboard (human approval) → raw draft → notes loop. Three additions come straight from the evidence. A mandatory storyboard and plan stage, because it was the largest measured lever in Code2Video. A layout grid and per-frame bounding-box log, with automatic overlap, safe-margin and leftover checks. And a short API reference for the engine, with a few-shot shot-function gallery and an explicit list of pitfalls (zero-scale cairo calls, still pockets, white flashes), instead of retrieval over the docs. Stills mode should sample **at least three frames inside every animation**, not one frame per shot.

**2. A second backend: HyperFrames, pinned.** Use it for shots where the browser beats pycairo: kinetic typography, captions, charts, maps, shader transitions and Three.js inserts. It also serves as a standalone mode for pure motion-graphics explainers. Choose it over Remotion for three reasons: the Apache-2.0 licence, plain HTML that a 27B model can write, and a bundled lint, check and snapshot loop. Its risk is churn. It is pre-1.0 and ships several releases a day, so lock the npm version and update deliberately. Steelman Remotion as the fallback. It is more mature, its 4.x API is stable, its skills are official, and you qualify for the free licence today. HeyGen's `remotion-to-hyperframes` skill also shows the two are close enough to port between ([HyperFrames guide](https://hyperframes.heygen.com/guides/hyperframes-vs-remotion)). Have HyperFrames shots render to frames on the same segment grid, and pass them through the same post pass (grade, grain, palette guard) so both backends look like one film. Verify alpha output early. If it is missing, render full-frame shots rather than overlays.

**3. A local-video skill** that mirrors local-image. It uses ComfyUI and versioned workflows for I2V, FLF, control-video and T2V, keeps seed and model sidecars, reviews takes best-of-N on contact sheets, then upscales and retimes with RIFE to 24 fps. Wan 2.2 is the default for licence clarity and LoRAs, and LTX-2.5 NVFP4 is the speed path. The first task is a timing run on your 5080, since no published number exists.

**4. Later, and optional: Blender 5.2 LTS** for shots that need real occlusion, depth, parallax or simple rigged characters, rendered to PNG passes and composited by the engine. Ship a 5.x cheatsheet and always run with `--python-exit-code`. **Manim CE** belongs here only if you want math explainers. In that case, pin 0.22 and use the community manim_skill and manimkit linter ([manim_skill](https://github.com/adithya-s-k/manim_skill), [manimkit](https://pypi.org/project/manimkit/)).

### The 20-second demo benchmark

The demo should exercise every failure the author noted in "Initial Condition", in 480 frames at 1080p and 24 fps. A good brief is "Ember": four voice lines of about 50 words in total, in one voice. For example: "Before the first fire, night was a wall. / Then a spark fell into dry grass, / and the dark stepped back. / We have fed it ever since." The brief comes with five hard requirements:

1. Two Qwen-Image plates (a night landscape and a hearth) with procedural vector layers on top.
2. A spark that falls in depth and is occluded by a foreground element, which tests physical logic and depth.
3. A flame that ignites on the word "spark" and a light wave that pushes outward on "stepped back", each within ±100 ms of its word.
4. One kinetic title on line 4 that must not collide along its path.
5. One plate-to-plate transition with a fade from black after the brightest frame, two or three SFX at most, no ducked music, and a clean fade to black at 20 s.

An optional arm adds one local-video I2V take of the hearth plate. The deliverables are the storyboard, `timeline.json`, the contact sheet, the in-motion stills, the final MP4 and a run log.

### Testing the agents fairly

Run two tracks, because the local model creates a confound. **Qwen 27B on llama-server occupies the same 16 GB card that local-image, local-voice and local-sounds need**, and an agent cannot unload itself mid-run. Track A, "frozen assets", gives every arm the same script, storyboard, voice takes with word timings, plates and SFX, and measures only code-writing and the review loop. Track B, "idea to film", starts from the one-line idea and includes tool calls. For the Qwen arm it uses an asset queue that runs between agent sessions. A third, small Track C tests the role the LESSONS file predicts for the local model. It gives each arm ten well-specified shot functions (spec, cue specs, a reference still) and scores how many pass the stills check within N fix attempts. Arms in the first two tracks are Opus, Sonnet, Haiku, Qwen 27B alone, and Qwen 27B as a shot worker under an Opus or Sonnet director. Run Sonnet and Qwen with and without the skill as well.

Hold everything else constant. Use the same skill commit, engine version and framework pins, the same prompts, the same wall-time and render-iteration caps, and **three runs per arm**, reporting the median and spread. HeyGen's top models sat within 12 Elo of each other, so a single run cannot separate them ([HeyGen Research](https://www.heygen.com/research/introducing-code2video-benchmark)). Claude Code and the local-agent harness (pi or OpenCode) differ. Where possible, also run Sonnet through the Qwen harness so that model effects separate from harness effects.

Score in three layers. **Automatic gates** check that the render completes, the duration is within ±0.5 s, every cue lands within ±100 ms, and the bounding-box log shows no overlaps or margin breaches, plus the palette and loudness checks. **A rubric** covers the LESSONS checklist categories (proportion, composition, physical logic, transitions, readability, leftovers, sound, subtitles) on the contact sheet and in-motion frames. **Blind human pairwise preference** with order swapped is aggregated to Elo. Use a VLM judge only as a secondary signal. In TheoremExplainAgent's validation its scores correlated with humans at just 0.14-0.72 Spearman depending on the dimension ([TheoremExplainAgent](https://arxiv.org/html/2502.19400)). Log tokens, cost, wall time, GPU time and render count. The metric that matters most is **how many human notes, over at most three rounds, it takes to reach "good"**. Give the notes verbatim, written by someone who does not know which arm made the film. For scale, Code2Video's agent spent 9-17 minutes and 19-49K tokens per video, against about 2 minutes and 1-2K tokens for writing the code directly ([Code2Video](https://arxiv.org/html/2510.01174)).

## Conclusion

The research reframes the original question. The framework choice is no longer the main decision, because the cross-model evidence shows quality comes from structure the agent is given. That structure is a plan it must commit to, timing it cannot improvise, a layout it can check by machine, and frames sampled mid-motion. "Initial Condition" already built the hardest part of this: timing driven by word timestamps. What it lacked is the part the papers measured, which is a layout log and a planner stage enforced as gates, not left to the agent's judgement. Treat frameworks as interchangeable picture backends behind one `timeline.json`. Then HyperFrames, Blender or a video model can be added or dropped without rewriting the method. And Remotion's licence or HyperFrames' churn stays a contained risk, not a foundation risk.

The second implication concerns the local model. Its biggest constraint on this machine is likely to be the 16 GB card it shares with every asset tool, not its intelligence. Even a strong 27B coder cannot direct a film whose voice, plates and sounds need the same GPU it occupies. The realistic local role is the one the evidence on tight renderer loops supports: a shot-function worker that renders and fixes its own stills, under a frontier-model director or between asset batches. The benchmark should be built to confirm or refute that before the skill commits to it.
